Give CI jobs access to private infrastructure without giving them the whole network.

CI/CD is one of the clearest use cases for SkiMasque.

Get StartedRead the Docs

The problem

A deployment job may need to reach:

  • database
  • private API
  • Kubernetes API
  • internal service
  • cloud control endpoint

The traditional answer is often a VPN or VPC route from the CI runner into the private network.

SkiMasque makes the access specific to the job.

Lifecycle of a CI session

The GitHub Action

The action exchanges the runner's OIDC token for a short-lived credential and sets ALL_PROXY to a local SOCKS5 relay. Tools that honour ALL_PROXY can then reach, through the gateway, only what your policy allows.

CI/CD integrations

Supported today:

  • GitHub Actions
  • generic OIDC
  • GitLab CI
  • Buildkite

Terraform and other command-line applications are the typical use case: any tool that honours ALL_PROXY can run behind the action.

Architecture should remain extensible to:

  • CircleCI
  • Jenkins
  • other workload identity providers
